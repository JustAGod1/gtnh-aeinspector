# AE Inspector 0.1.11 — состояние GUI и возврат из I/O

После Esc и повторного открытия инспектор восстанавливает период, сортировку, фильтр предметов/жидкостей, поиск, выбранные ресурсы и прокрутку. Масштаб GUI и высота списка сохраняются, как раньше. Период, сортировка, фильтр и поиск записываются в существующий `config/aeinspector-client.cfg` и переживают перезапуск игры. Выбор ресурсов и прокрутка хранятся до конца текущего подключения: числовые ID из одного словаря мира не применяются к другому миру.

Кнопка **Назад**, **Esc** и боковая кнопка мыши **Назад** (Mouse 4) возвращают из I/O к тому же основному экрану. Его графики, выбранные ресурсы, поиск, период и позиция списка сохраняются. Смена периода в I/O относится к списку устройств и не заменяет период основного экрана.

Пока открыт I/O, главный экран продолжает получать и применять обновления. Сервер поддерживает две независимые подписки внутри одного открытого контейнера; ответы маршрутизируются по собственным ревизиям. Возврат отменяет только запросы I/O и не запускает заново запрос статистики. Полное закрытие инспектора отменяет обе подписки и освобождает клиентские буферы ответов. Обычный сбор статистики сети по-прежнему продолжается независимо от GUI.

Новых потоков нет. Обе серверные подписки используют существующую общую очередь с мягким бюджетом 2 мс на тик для всех зрителей; при открытом I/O клиент делит прежний бюджет декодирования между двумя окнами с чередованием приоритета. Открытый I/O теперь требует обновлений двух таблиц, поэтому трафик и объём работы выше, чем при обновлении одной таблицы. Фоновая обработка после полного закрытия GUI не добавлена. Расчёт потоков ресурсов, единицы графиков и NBT истории не менялись.

## Проверки

`test reobfJar`: **95 тестов без ошибок**. Новые проверки покрывают восстановление настроек и независимость копий выбора, чтение конфигурации после перезапуска, ограничение некорректных настроек, защиту от переноса ID в другое подключение, одновременные ответы главного окна и I/O, отмену только одной подписки, отказ от устаревших запросов, повторное открытие I/O и отмену обеих задач при закрытии контейнера. Игра и нагрузочные сценарии не запускались.

## Установка и ручная проверка

Нужно заменить JAR **на клиенте и сервере** и полностью их перезапустить. Протокол запросов изменился; смешивать 0.1.11 с более ранними версиями не следует. Для одиночной игры достаточно обновить JAR инстанса. История NBT не требует конвертации.

1. Выберите 10 минут, сортировку, фильтр и несколько ресурсов, введите поиск, прокрутите список. Закройте инспектор через Esc и откройте: эти настройки должны восстановиться.
2. Откройте I/O любого ресурса и подождите несколько обновлений. Вернитесь боковой кнопкой мыши: прежний выбор и список должны показаться сразу, а графики содержать свежие данные.
3. Повторите возврат через Esc и кнопку «Назад», в том числе во время загрузки I/O и после смены его периода. Основной экран должен сохранить свой период.
4. Полностью закройте инспектор из I/O нажатием клавиши инвентаря либо кликом по устройству для подсветки. При повторном открытии должны восстановиться настройки главного экрана.
