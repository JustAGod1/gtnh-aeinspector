# AE Inspector 0.1.7 — Storage Bus и расширяемый список

## Изменения

Кастомные хранилища за Storage Bus теперь наблюдаются через общий API AE. До этого перехваты внешних изменений работали только в штатных `MEMonitorIInventory` и `MEMonitorIFluidHandler`; блок со своим `IMEMonitor` обходил их. Новый путь не проверяет класс Super Chest, не читает его внутренние поля и не добавляет зависимость от GregTech. Штатные мониторы сохраняют существующие перехваты, чтобы не сканировать их повторно.

`InventoryMonitorObservation` подписывается на `IMEMonitor.addListener`. Уведомление `postChange` помечает адаптер для сверки, без предположений об источнике события или времени вызова. При сверке сравнивается полный `getStorageList()` с предыдущим снимком и вычитается сумма фактически выполненных операций AE между снимками:

```
внешнее изменение = текущий запас − предыдущий запас − операции AE
```

Положительный остаток записывается как приход, отрицательный — как расход; устройство в I/O — подключённый Storage Bus. Все варианты metadata/NBT по-прежнему разрешаются в отдельные точные ключи; счётчики 64-битные. Операции терминала и резервирования CPU тоже вычитаются при сверке, поэтому сами по себе не превращаются во внешнее производство/расход.

Записи операций AE также ставят адаптер на сверку: это покрывает случай, когда AE забрала 64 предмета, автоматика восполнила 64, а монитор не прислал уведомления о нулевой суммарной дельте. Есть дополнительная проверка примерно раз в 20 тиков; обычный `IMEInventory` без уведомлений читается через `getAvailableItems`. Несколько уведомлений объединяются в одну задачу. Один экземпляр адаптера имеет один наблюдатель; повторные подключения в одной сети не умножают внешнюю дельту.

Первое чтение, новое подключение, изменение сети/питания и `onListUpdate` устанавливают новую исходную точку. Изменение видимости не считается перемещением всего содержимого. При удалении устройства подписка снимается. Представления другой ME-сети исключены из нового наблюдателя: их передачи учитываются существующими сетевыми перехватами.

Нижний список ресурсов можно растягивать за разделитель над заголовком: вверх — больше строк, вниз — больше места графикам. ПКМ возвращает исходный размер. Настройка сохраняется в `config/aeinspector-client.cfg`. Растягивание, колесо и ползунок работают с уже полученным списком, без запроса или экрана загрузки. I/O-кнопки и ползунок перестраиваются под новую высоту.

## Ограничения

- Внешние изменения — оценка разности снимков. Если между двумя чтениями извне добавили и извлекли одинаковое количество, отдельно восстановить оба потока нельзя. Время записи — тик обнаружения изменения.
- Общий путь предполагает, что адаптер соблюдает контракт AE: возвращает актуальные количества и сообщает смену доступности. Произвольную скрытую смену видимости нельзя отличить от реального изменения запаса. `onListUpdate` трактуется как смена доступности, согласно API AE.
- Очередь сверок выполняется в серверном потоке с общим мягким бюджетом 1 мс на тик, не более одного чтения адаптера за тик. Вызов стороннего `getStorageList`/`getAvailableItems` и обработка одного снимка неделимы: один медленный адаптер может превысить бюджет. При накоплении работы обновление статистики задерживается. При ошибке чтения она записывается в лог, исходный снимок сбрасывается и чтение повторяется с паузой; ошибочный интервал не превращается в фиктивный поток.
- Собственных потоков нет. История продолжает сохраняться стандартным NBT мира; формат истории и сетевой протокол 0.1.5 не изменены. Пропущенные предыдущими версиями внешние изменения задним числом восстановить нельзя.

## Проверка и установка

`test reobfJar`: 81 тест без ошибок. Новые проверки охватывают начальный снимок, положительные/отрицательные дельты, частичные операции AE, задержанные и отсутствующие уведомления, совпадающие удаления/пополнения, переподключение, смену видимости, жидкости, новые объекты стека и количества больше `int`. Два теста проверяют точки перехвата в байткоде закреплённых AE2/AE2FC; отдельный тест проверяет геометрию расширяемой таблицы.

Игра и нагрузочный бенчмарк не запускались. Проверка байткода не заменяет проверку применения Mixins и поведения блоков в GTNH.

Замените старый JAR на **AE-Inspector-0.1.7.jar** на клиенте и сервере, затем перезапустите игру. Для ручной проверки:

1. Подключите Super Chest или другое хранилище к Storage Bus. Дождитесь исходного снимка; уже лежавшие предметы не должны появиться как производство.
2. При остановленных передачах AE добавьте извне 64 предмета, подождите пару секунд, заберите 16. В периоде проверки должны добавиться 64 прихода и 16 расхода; в I/O — этот Storage Bus с его координатами.
3. Включите Export Bus и одновременно внешнее пополнение. Изъятие AE не должно дублироваться как дополнительный расход Storage Bus, а внешнее пополнение должно учитываться даже при неизменном запасе.
4. Отключите/подключите кабель или питание: не должно возникать всплесков размером со всё содержимое. Проверьте аналогичный сценарий с жидкостью и обычным сундуком.
5. Потяните разделитель списка, прокрутите его, нажмите I/O в одной из новых строк. Перезапустите GUI и проверьте сохранение высоты; ПКМ по разделителю должен её сбросить.
