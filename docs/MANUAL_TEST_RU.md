# Ручная проверка AE Inspector 0.1.0

Это экспериментальная сборка для проверки в GTNH 2.8.4. Полная функциональность и производительность ещё не подтверждены.

## Установка

1. Для первого прогона используйте отдельный тестовый мир или копию мира.
2. Положите **один** файл `AE-Inspector-0.1.0.jar` в `mods` клиента и сервера. В одиночной игре достаточно клиента. Удалите предыдущую копию AE Inspector, если она уже установлена.
3. Используйте штатные зависимости GTNH 2.8.4: AE2 `rv3-beta-695-GTNH`, AE2FC `1.4.120-gtnh`, UniMixins `0.1.23`. Дополнительных зависимостей от GregTech у мода нет.
4. Файлы с суффиксом `-dev.jar` и `aeinspector-smoketest.jar` устанавливать не нужно.

## Получение и открытие

- Рецепт: обычный AE wireless terminal + calculation processor, без формы. Заряд и привязка должны перейти в инспектор.
- Для быстрого теста: `/give @p aeinspector:inspector 1`. Зарядите его и привяжите через терминал безопасности ME, как обычный беспроводной терминал.
- Нужна работающая беспроводная точка доступа той же сети. Открытие — правой кнопкой.
- Поиск и сортировка находятся сверху. Клик по ресурсу выбирает график, Shift + клик добавляет ресурс к сравнению; максимум восемь.
- Девять кнопок выбирают масштаб двух графиков: приход и расход. Количество относится к выбранному периоду, средняя скорость показана в минуту.
- Кнопка I/O в строке ресурса открывает отдельный экран его устройств. Щелчок по известному устройству включает штатную подсветку AE2. «Назад» или Esc возвращает к статистике.

## Первый короткий прогон

1. **Открытие и рецепт.** Зарядите и привяжите wireless terminal, улучшите его рецептом. Проверьте перенос привязки/заряда, открытие инспектора и закрытие при выходе из радиуса.
2. **Импорт/экспорт.** Import Bus забирает уголь из сундука в ME, Export Bus отправляет его в другой сундук. Выберите уголь и масштаб 1 минута. Должны появиться приход, расход и обе шины с координатами. По очереди остановите каждую шину, чтобы проверить направления.
3. **Подсветка.** Щёлкните по каждой шине в списке. Должен подсветиться соответствующий блок в мире.
4. **Ручные действия.** Переложите уголь через обычный ME Terminal. Эти операции не должны создавать поток на графике.
5. **NBT и metadata.** Импортируйте несколько вариантов одного предмета с разными metadata/NBT. Они должны оставаться разными строками и ID, даже если названия совпадают.
6. **Перезапуск.** Штатно сохраните и перезапустите мир. На достаточно крупном масштабе должны сохраниться прежняя история и различия вариантов.

## После первого прогона

- Проверьте жидкости с Discretizer и без него: единица — mB, преобразование Fluid Drop не должно удваивать поток.
- Проверьте экспорт в почти полный резервуар: расход должен соответствовать фактически принятому объёму; возврат остатка не должен выглядеть как производство.
- Закажите автокрафт с промежуточными продуктами: например, брёвна → доски → палки. Резерв CPU не должен считаться расходом; передача ингредиентов исполнителю и фактическое получение промежуточных продуктов должны учитываться.
- Отмените крафт до передачи ингредиентов, затем отдельный крафт после частичного исполнения. Неиспользованный резерв нейтрален, уже произошедшие передачи остаются.
- Измените содержимое сундука за Storage Bus внешним способом. Его изменение должно учитываться как оценка, без повторного учёта известных операций AE.

## Известные ограничения этой сборки

- Настроенные простаивающие устройства, ещё не имевшие передач, пока не добавлены в список устройств.
- Экран ещё не прошёл визуальную проверку: возможны тесные подписи/таблица при небольшом размере окна. Отдельное обозначение оценочных данных и отображение всех итогов требуют доработки.
- Сложные игровые сценарии и нагрузка не проверены. Цель p95 ≤ 1 мс/тик для всего учёта пока не подтверждена.
- Хранение, запросы и учёт однопоточные; на медленном диске возможны задержки сохранения. Полная проверка восстановления после аварии ещё впереди.

## Что сообщить по результатам

Достаточно написать: какой пункт проверяли, что ожидали, что получилось. Для неправильных чисел полезны количество переданных ресурсов, выбранный масштаб и схема подключения. Для проблемы экрана полезны снимок и GUI Scale. При падении нужен соответствующий crash-report или хвост `logs/fml-client-latest.log` / серверного лога с исключением.

Автоматическая проверка этой сборки: 27 тестов прошли; игровой JAR собран. Ранее в настоящем клиенте Forge проверено применение четырёх основных Mixins. Новый перехват операций шин с вычитанием возвратов прошёл компиляцию и модульные тесты, но его игровой прогон оставлен для ручной проверки.
